# 大语言模型 API 使用指南

## DeepSeek API

本项目通过 OpenAI Python SDK 调用 DeepSeek,base_url 配置为 https://api.deepseek.com。模型名在 src/config.py 中设置,使用前需确认账号支持该模型。

调用方式与 OpenAI SDK 一致:安装 openai 包,创建客户端时指定 base_url 和 api_key,然后调用 chat.completions.create 方法。支持流式输出(stream=True)、JSON 模式输出、函数调用等特性。

API 按 token 计费,输入和输出分开计价,命中缓存的输入 token 价格更低。对于 RAG 场景,系统提示词和检索上下文往往较长,实际费用取决于服务商计费规则和缓存命中情况。

## 温度参数与采样

temperature 参数控制生成的随机性:较低的取值通常减少采样随机性,但不保证多次调用的结果完全一致。RAG 问答场景通常设置 temperature 为 0 到 0.3,因为我们希望回答严格基于检索到的上下文,而不是自由发挥。

top_p(核采样)是另一种控制随机性的方式,与 temperature 二选一调整即可,不建议同时调整两者。

## 提示词工程要点

本项目的提示词包含以下约束:

明确角色和任务边界:告诉模型"你只能基于提供的上下文回答,上下文中没有的信息要明确说不知道",但提示词本身不能保证消除幻觉。

上下文结构化:把检索到的多个文档块用编号和来源标注清晰分隔,如 [文档1 来源:xxx.pdf],方便模型引用和用户溯源。

引用要求:要求模型在回答中标注每个论断的来源编号,如"根据 [文档2]……",方便读者回到原文核对,引用编号本身不代表论断正确。

输出格式约束:如果需要结构化输出,给出明确的格式示例,或使用 JSON 模式。
